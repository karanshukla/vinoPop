# Changelog

All notable changes to vinoPop are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Generated by [git-cliff](https://git-cliff.org) from conventional commits, then
hand-refined. The release workflow reads its notes from here, so edits stick.

## [Unreleased]

## [1.7.0] - 2026-11-11

### ✨ Features

- Settings > Advanced > Offline AI lists the downloaded AI models with their size and deletes them. Deleting also turns off the background download, so the model doesn't come straight back.

### 🐛 Bug Fixes

- Uninstalling deletes the AI model and its compile cache, not only with `--purge`. Settings, snippets and clipboard history stay unless you add `--purge`.

## [1.6.0] - 2026-11-08

1.5.0 is skipped: it was released and withdrawn on 2026-11-05 (it became 1.4.1), so an install that picked it up is offered this one.

### ✨ Features

- Settings > Text labels: popup buttons show each action's name as plain text instead of its icon.
- About vinoPop lists vinoPilot, the app that installs and updates the others, with the rest of the family.

### 🐛 Bug Fixes

- Installing from a checkout removes a release install's app link and `vinopop-upgrade`, so the two don't both stay installed.

### ♻️ Refactor

- The tray menu no longer lists vinopilot.ca and the other vinoPilot apps; About vinoPop still links to them.

## [1.4.1] - 2026-11-05

### 🐛 Bug Fixes

- The NPU doctor's driver and compiler hints work on Fedora Atomic (Bazzite, Silverblue, Kinoite): `rpm-ostree install` and a reboot instead of `dnf`, and the compiler goes in `/usr/local/lib64` with an `ld.so.conf.d` entry instead of the read-only `/usr/lib64`.
- openSUSE Tumbleweed and Leap 16 get the NPU driver from their own repos (`libze_intel_npu1` with `level-zero`), through `zypper`, or `transactional-update` and a reboot on Aeon, Kalpa and MicroOS.
- Install hints for other image-based systems: `rpm-ostree` is only suggested on Fedora-family hosts (Endless OS boots ostree without it), and a read-only `/usr` (SteamOS, Vanilla OS) no longer gets `sudo pacman` or `sudo apt` lines.
- `install.sh` and `get.sh --with-ai` prefer `/usr/bin/python3`, so on Bluefin and Aurora Homebrew's Python (which has no `gi`) isn't written into the launchers.
- The OCR row tells release installs to run `vinopop-upgrade --with-ai` instead of `pip install --user`, which missed the app's venv.
- `install.sh` says when dbus-python is missing on KDE Plasma Wayland, where the hotkey otherwise never fires, and `get.sh` writes `vinopop-upgrade` before running `install.sh`, so a failed dependency check can be rerun.

## [1.4.0] - 2026-11-05

### ✨ Features

- One-line install from a GitHub release: `curl -fsSL https://github.com/karanshukla/vinoPop/releases/latest/download/get.sh | bash` (`-s -- --with-ai` for the offline AI). Releases now ship a tarball with a `VERSION` file and `SHA256SUMS`; `get.sh` checks the tarball, unpacks it into `~/.local/share/vinopop` behind an `app` link and runs its `install.sh`.
- Settings > Advanced > Updates: Check for updates, then Update to vN, then Restart. Nothing goes online until you click it. It runs `vinopop-upgrade`, the copy of `get.sh` the installer keeps.
- The tray links to vinopilot.ca and the other vinoPilot apps, with the menu icons the other vinoPilot trays use.

### 🐛 Bug Fixes

- An install without `.git` (a release tarball) showed version 0.0.0; it reads the tarball's `VERSION` file now.
- Check for updates on a git clone past a tag said "vinoPop 1.3.0-5-g… is the newest release". It says it's a development build and names the newest release.

### 🎨 Look and feel

- **The windows follow the GNOME HIG more closely.** Settings rows drop their
  coloured badge circles for plain rows, as in GNOME Settings, and hotkeys show
  as keycaps (`Gtk.ShortcutLabel`) instead of raw `super+shift+y` text. List
  rows use plain Install/Remove buttons and flat icon buttons, keeping the
  coloured styles for a view's one main action.
- **The clipboard picker uses a view switcher.** Recent and Snippets are an
  `Adw.ViewStack` with an inline `Adw.ViewSwitcher` instead of notebook tabs,
  with the lists in a card and a shorter keyboard hint.
- **Dialogs are `Adw.Dialog`s.** The recipe wizard, the icon picker and the
  Settings text editors attach to the window they were opened from.
- **AppStream metainfo.** `install.sh` installs
  `data/io.github.karanshukla.vinoPop.metainfo.xml`, so GNOME Software and KDE
  Discover can describe vinoPop. `--uninstall` removes it.
- Copy fixes: no more `--` dashes, header capitalisation on headings and
  buttons, and the welcome dialog mentions the app grid as well as the tray.

## [1.3.0] - 2026-11-01

### ✨ Features

- **Read aloud, with vinoSpeak.** A new Read aloud action speaks the
  selection on the NPU, falling back to GPU or CPU, and unloads the voice
  when idle like the LLM. A "Reading aloud" notification has a Stop button,
  and while it plays vinoPop shows up as a media player, so the media keys,
  KDE's and GNOME's player widgets and the lock screen can stop it. Needs the
  `ai` extra (`vinospeak`); doctor checks the package and the voice download.
- **`vinopop --trigger popup|ocr|clipboard`, for shortcuts set in the
  desktop's own settings.** Off KDE the hotkeys are XWayland grabs, which
  miss native Wayland apps. Binding this command in GNOME, sway, Hyprland or
  COSMIC works whatever has focus; the README says where.
- **Opening vinoPop again shows the running copy's Settings** instead of only
  saying it's already running.

### 🐛 Bug Fixes

- **Open path no longer runs programs.** Selecting a `.desktop` file, an
  AppImage, an `.exe` or any executable and clicking Open path launched it
  through xdg-open. It now opens the containing folder and says why.
- **The selection never appears in the media player's title,** so the start
  of a selected password or message can't be read from the lock screen. The
  title is always "Reading aloud".
- **OCR works on GNOME.** The screen grab falls back to the desktop's
  screenshot portal (cropped to the monitor under the pointer), the region
  picker ends with the portal's interactive one, and maim, which only sees
  XWayland, is skipped on Wayland.
- **The AI model leaves the NPU after a cancelled answer.** Dismissing a
  popup mid-answer skipped the idle unload, so Gemma kept ~2.5 GB pinned
  until the next completed run or a restart.
- **install.sh supports openSUSE and image-based distros** (Fedora Atomic,
  Aeon): the right package names, rpm-ostree or transactional-update hints
  when `/usr` is read-only, a Python 3.11 check, and a note when run inside a
  toolbox or distrobox. The OCR Install button no longer offers `pkexec dnf`
  on a read-only `/usr`, and installs the screenshot tool for your desktop.

### 🔧 Development

- Tests for text expansion, the Run-in-terminal confirm dialog, the
  `{shell:}` snippet gate and Compose email's mailto quoting.
- CI measures coverage in the GTK job with a floor, fails on new Bandit
  findings, and runs the AI tests and pip-audit weekly against the real
  OpenVINO stack.

## [1.2.0] - 2026-10-23

### ✨ Features

- **The AI bubble's Copy and Replace work from the keyboard.** When the popup
  was driven by keyboard, the bubble takes Left/Right/Tab, Enter and Esc the
  same way, highlights a chip and announces it.
- **OCR can pick its region from the keyboard.** Enter with nothing placed
  reads the whole screen; arrows place and move a box, Shift+arrows resize it,
  Ctrl takes bigger steps, and Enter reads it. The box is announced as it
  changes.
- **The tray icon can hide while vinoPop goes unused.** Settings has a new
  "Hide tray icon after (minutes)" row (`tray_idle_minutes`, default 0 =
  always shown), as vinoWhisper and vinoWatch do; the next popup, OCR or
  clipboard hotkey brings it back.

### 🐛 Bug Fixes

- **The OCR overlay comes up without freezing the app.** The screen grab and
  the pointer lookup ran on the GTK thread, so every OCR hotkey press froze the
  daemon for the length of the screenshot; they now run on the capture's own
  thread, and a fallback to the desktop's region tool is logged.
- **Typing accented letters and emoji over XTEST no longer mangles them under
  load.** Each character the layout lacks gets its own spare keycode for the
  whole string instead of rebinding one keycode per character.
- **Bundled Editing and Formatting plugins offer their update again.** A
  comment-only change without a version bump made installed copies look
  hand-edited. The plugins whose icons changed in 1.1.1 (Editing actions,
  HTML entities, Text transformations, the MDN docs recipe) are bumped too, so
  installed copies pick up the new icons.
- **Every action has its own icon, drawn at the system symbolics' size.**
  Decode, lower case and the like drew a mono glyph next to their encoding
  twin's colour tile, and five marks were text that depended on installed
  fonts (the translate one needed a CJK font). Every mark is a path now.
- **Screen readers can name every control.** Settings and Plugin Manager
  rows, the clipboard picker's entries, search fields, dialog fields and the
  AI bubble's close chip read as blank or as "✕"; the two "Disable hotkey"
  buttons now say which hotkey they set.
- **The onboarding tour respects reduced motion** and starts keyboard focus
  on Next. A page change is announced, and the welcome dialog closes on
  Escape.
- **Text you have to read to finish a step is no longer dimmed.** The
  wizard's instructions, the text-editor dialog's subtitle, the onboarding
  status line and the icon picker's count were ~3.2:1 on the light theme.
- **install.sh checks for GTK's SVG loader.** On a minimal Debian or Ubuntu
  install, `librsvg2-common` is only recommended, so every icon drew as
  image-missing. install.sh names the package, and the README's apt line
  includes it.

### 🔧 Development

- **xdotool is no longer needed.** The XWayland backend types text and sends
  every key over XTEST with python-xlib, binding a spare keycode for
  characters the layout lacks, the way xdotool did. Doctor, install.sh and the
  README stop listing it.
- UI labels that lead to another window end in an ellipsis character, as the
  GNOME HIG asks.

## [1.1.0] - 2026-10-20

### 🚀 Features

- **The AI bubble says when the model is compiling.** A load with no compile
  cache now shows "Compiling the model for NPU, one time only…" with a running
  timer, instead of the same "Loading model" a cached 2s load shows
  ([#113](https://github.com/karanshukla/vinoPop/pull/113)).
- **`vinopop --doctor` checks the NPU before anything loads**: PCI device,
  kernel driver, `/dev/accel` permissions, the level-zero backend and compiler,
  and whether this OpenVINO is known to work with the installed NPU driver.
  Every row has a group and, when something is wrong, the command that fixes
  it ([#110](https://github.com/karanshukla/vinoPop/pull/110)).
- **The popup hotkey toggles the popup**, and the bar can be driven from the
  keyboard on X11 ([#105](https://github.com/karanshukla/vinoPop/pull/105)).
- **Settings links to the Plugin Manager**, which now uses the Settings layout
  ([#101](https://github.com/karanshukla/vinoPop/pull/101)).

### 🐛 Bug Fixes

- **Model downloads are verified file by file.** Every file is checked against
  a pinned sha256, a download only replaces the model once it's complete, and
  stale compile caches are pruned. Gemma 4 E4B is pinned too
  ([#109](https://github.com/karanshukla/vinoPop/pull/109)).
- **Upgrading no longer downloads the model again.** A model folder from before
  the download markers is checked and kept when every file matches, and the
  progress line no longer counts each byte twice (9.0 GB for a 4.5 GB model)
  ([#111](https://github.com/karanshukla/vinoPop/pull/111)).
- **Icons Breeze 6.31 dropped** (`emoji-people`, `view-list`, `insert-object`)
  fall back to ones it still ships, instead of drawing nothing on KDE
  ([#112](https://github.com/karanshukla/vinoPop/pull/112)).
- **`install.sh --uninstall` lists what's left**, and `--purge` deletes it:
  settings, snippets, clipboard history, the AI model and the KDE shortcuts
  ([#109](https://github.com/karanshukla/vinoPop/pull/109)).
- **install.sh** escapes odd checkout paths in the launchers, accepts
  `VINOPOP_PYTHON=python3.12` by name, and gives install hints for the distro
  it runs on ([#108](https://github.com/karanshukla/vinoPop/pull/108)).
- The AI bubble and the popup bar stay inside the screen
  ([#102](https://github.com/karanshukla/vinoPop/pull/102)).
- Notifications come from vinoPop, not notify-send
  ([#103](https://github.com/karanshukla/vinoPop/pull/103)).

### 🔧 Development

- `uv run poe check` works on a fresh clone, and CI runs the GTK tests
  ([#108](https://github.com/karanshukla/vinoPop/pull/108)).
- Tagging `v*` publishes a GitHub release with its notes from this file, a
  weekly canary installs the AI stack fresh, a test checks
  `install.sh --uninstall --purge` leaves nothing behind, and commit subjects
  have to be conventional ([#114](https://github.com/karanshukla/vinoPop/pull/114)).
- The XWayland backend sends keystrokes over XTEST with python-xlib; xdotool
  is only a fallback ([#106](https://github.com/karanshukla/vinoPop/pull/106)).
- Modules are grouped into packages
  ([#100](https://github.com/karanshukla/vinoPop/pull/100)).

## [1.0.0] - 2026-10-19

First release as vinoPop. It started as a fork of
[LinuxPop](https://github.com/GaimsDevSoftware/linuxpop) 0.9.7, and since then
the UI moved to GTK 4, the AI moved on-device, and the online integrations are
gone.

### Highlights

- **Offline AI on the NPU.** Summarize, rewrite, explain and translate run
  Gemma 4 E2B (or E4B) through OpenVINO, with GPU/CPU fallback. Screen OCR runs
  on the CPU and can describe the captured image
  ([#4](https://github.com/karanshukla/vinoPop/pull/4),
  [#14](https://github.com/karanshukla/vinoPop/pull/14),
  [#68](https://github.com/karanshukla/vinoPop/pull/68)).
- **GTK 4 and libadwaita**, with the vino family palette and icons, a sidebar
  Settings window and working light mode
  ([#5](https://github.com/karanshukla/vinoPop/pull/5),
  [#42](https://github.com/karanshukla/vinoPop/pull/42),
  [#73](https://github.com/karanshukla/vinoPop/pull/73),
  [#76](https://github.com/karanshukla/vinoPop/pull/76)).
- **A stuck NPU no longer crashes it.** A subprocess probe catches the
  segfault, loads on the GPU and tells you how to reset the driver
  ([#40](https://github.com/karanshukla/vinoPop/pull/40),
  [#98](https://github.com/karanshukla/vinoPop/pull/98)).
- **KDE Wayland input that works**: portal key injection, keyd-proof
  double-click, layout-aware keycodes, one KWin helper for lower popup latency
  ([#58](https://github.com/karanshukla/vinoPop/pull/58),
  [#62](https://github.com/karanshukla/vinoPop/pull/62)).
- **Privacy**: no online plugins, OpenVINO telemetry blocked outright,
  selections kept out of the log, password-manager copies skipped by clipboard
  history, recipes pass text as arguments instead of shell source
  ([#1](https://github.com/karanshukla/vinoPop/pull/1),
  [#48](https://github.com/karanshukla/vinoPop/pull/48),
  [#49](https://github.com/karanshukla/vinoPop/pull/49),
  [#72](https://github.com/karanshukla/vinoPop/pull/72),
  [#82](https://github.com/karanshukla/vinoPop/pull/82)).
- **Robustness**: survives a bad `settings.json`, bad plugin or recipe files,
  and flaky model downloads (resumable, checked, pinned revisions)
  ([#15](https://github.com/karanshukla/vinoPop/pull/15),
  [#51](https://github.com/karanshukla/vinoPop/pull/51),
  [#77](https://github.com/karanshukla/vinoPop/pull/77)).
- Runs as `vinopop`, with `vinopop --doctor` for AI diagnostics
  ([#71](https://github.com/karanshukla/vinoPop/pull/71)).

### Breaking

- Renamed from LinuxPop. On first run the `linuxpop` config, cache and data
  folders move to `vinopop`, so settings, plugins, snippets and history carry
  over.
- GTK 4.14+ and libadwaita 1.5+ are required (Ubuntu 24.04, Fedora 40,
  Debian 13 or newer).
- Flatpak and distro packages are gone for now. Install from source with
  `install.sh`.

### Known rough edges

X11 has had less recent testing than KDE Plasma 6 / Wayland, and native
Wayland is KDE only (other compositors run under XWayland).

Versions before 1.0.0 are LinuxPop's; see its
[releases](https://github.com/GaimsDevSoftware/linuxpop/releases).
